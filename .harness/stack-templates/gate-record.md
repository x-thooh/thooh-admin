# 模板：门记录（一次门禁跑完留下的东西）

复制这份到 `.harness/deliverables/gates/<UTC 时间>-<批次>.md`，填完再提交。
它不是日志：日志记发生了什么，门记录记**这一关是怎么过的**（或为什么没过）。

```text
批次：<本批只改了这一类东西>
命令：make check-all
退出码：0 | 1 | 2      # 2 = 前置条件不满足，不是通过
改前基准：ERROR <n> / WARN <n>（证据文件：<path>）
改后：ERROR <n> / WARN <n>
新欠逐条：            # 不许只报计数；「修掉一条老的、新增一条新的」在计数上会互相抵消
  - <scope> <code> <path>：<为什么是这次改出来的>
上升归因：<每条都要有一句原因；说不出原因不许交付>
判不了：<scope:项>——这不是通过
commit：<sha>
```

三条填法上的规矩：

- **「改前基准」必须是原样粘贴**，不是概括。概括句会在下一次对照时变成猜。
- 退出码 2 与「0 ERROR」不是一回事：前者是前置条件没满足（工作区脏、不是 git 仓库）。
- 证据时效由 `BLD002` 判（限时而非禁止：N 天 WARN、2N 天 ERROR），所以这份记录要么当场写，
  要么别写。
